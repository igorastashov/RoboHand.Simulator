# Цанга: вход и независимое ревью

[Документация Simulator](../../docs/index.md) · [Настройка MCP](../../docs/research/2026-11-09-kompas-mcp-setup.md) · [Исходное вложение](source-drawing.png).

Владелец явно поручил CAD-агенту построить модель по приложенному чертежу; root разбирает источник и принимает результат. Это отдельный CAD-тест, не новая конфигурация EB300. Модель создаётся в новом документе; исходная сборка EB300 и другие документы не изменяются/не закрываются.

**Итог:** принята ревизия R7: [нативная M3D](collet-r7.m3d), [STEP](collet-r7.step), [STL](collet-r7.stl), [чистое превью 300dpi](preview-r7-300dpi.png). Геометрия создана штатными инструментами установленного MCP в КОМПАС v25 Study. Исходные допущения ниже сохраняются; соответствие всему производственному чертежу без оговорок не заявляется.

[Технический отчёт CAD-агента](technical-report.md) · [Покрытие деталей чертежа](coverage-ledger.md).

Источник — ровно последнее изображение, предоставленное пользователем в текущем диалоге: PNG 1009×723, SHA256 `01f8288424ceedbb228f0259e6538d777c20b0a3aabb234becd7495b2288e905`. Сохранён без перерисовки. Детальные crops используются только для чтения; увеличение не восстанавливает отсутствующие пиксели.

## Согласованный профиль и явные допущения

Координаты ниже — осевая x от переднего торца и радиус r, мм; реальные global axes CAD проверить отдельно.

- Отверстие: r6.35 до x5 → конус70° до x9.141629/r9.25 → цилиндр до x88.5 → внутренняя фаска к x90/r10.75.
- Основной наружный профиль: r25 до x14.5 → фаска60° к x15.5/r23.267949 → вертикаль до r18.5 → R5 с центром(20.5,18.5), от(15.5,18.5) до(20.5,13.5) → r13.5 до x90.
- **Допущение front lip:** 1.2 относится к теоретическому пересечению начала перехода; наружная фаска Ø52.5→Ø50 принята60°, параллельно задней фаске, поскольку отдельный её угол явно не задан. Осевая длина без радиусов 1.25/tan60°=0.721688. Не выдавать эту часть за однозначное чтение.
- R0.3 front: центр(0.3,25.95), от(0,25.95) до(0.3,26.25). R0.3 rear lip: центр(1.026795,25.95), от(1.026795,26.25) до(1.286603,26.1); далее переход к(1.921688,25).
- Угловая фаза лысок относительно прорезей не определена размером; выбранную ориентацию записать как допущение.
- Готовый SDK `ksThreadDefinition` описывает условное изображение резьбы. Разрешён native cosmetic thread на своей цилиндрической поверхности с обозначением M20×1.5−6H/L50. При таком исполнении solid/STEP/STL не содержат геометрии витков; 6H сохраняется обозначением, если отдельное API-поле отсутствует.

## Критерии ревью

Проверить native feature tree и параметры, длину/радиусы/переходы, реальную топологию трёх прорезей и двух лысок, состояние thread feature, число тел, volume/mass и экспорт. После прорезей AABB может немного отличаться от номинального диаметра при снятом апексе окружности; Ø52.5 проверять также по поверхности/профилю. Справочную массу0.38 не использовать для подгонки геометрии или плотности.

Приняты .m3d и штатные STEP/STL, реальное preview. Незакрытые параметры и условное представление резьбы показываются явно. История попыток не перезаписана; ревью не скрывает неудачные первоначальные команды.

## Проверенный результат

- Native kernel: один body, V=48247.789214051445 мм³, масса0.3787451453303038 кг при принятой плотности7.85 г/см³. Независимый предварительный расчёт48247.419503 мм³ был приближённым; отличие0.369711 мм³ не использовалось для изменения геометрии.
- CAD-agent проверил три width1.7, равные angular gaps120° и окончания пазов x45; две плоские грани Y=±12 на X80…90. Номинальные профили Ø52.5/50/27 и общая длина90 сохранены.
- Native cosmetic thread создан: dr20/p1.5/length50/outside=False, base surface cylinder r9.25, begin face X90. Геометрический объём после thread не изменился; геометрии витков в solid/STEP/STL нет, 6H сохранено обозначением.
- Root открыл финальное PNG968×1001 и проверил отсутствие больших служебных плоскостей; вспомогательные объекты скрыты только у своей детали. После изменения вида native V/body/mass остались прежними.
- Независимый разбор binary STL: 1728 facets, осевая длина90 мм; volume48174.649539 мм³, отличие от native−0.151592% из-за тесселяции. При склейке координат до1e−5 мм: открытых рёбер0, nonmanifold0, вырожденных треугольников0. [Метрики](stl-review-final.json).
- R7 triangle payload побайтно совпал с проверенным R5; повторных CAD-вызовов ради той же проверки не делали. STEP содержит1 MANIFOLD_SOLID_BREP и SI_UNIT(.MILLI.,.METRE.). Файлы M3D/STEP/STL/PNG существуют, их SHA256 сверены root.

## Измеренная длительность

По timestamp пользовательского запроса в текущем диалоге и mtime созданных файлов (UTC): запрос2026-11-09T12:34:33.998Z; первая полная M3D R5 —13:01:53.931587Z; чистое финальное PNG R7 —13:11:08.189152Z.

| Этап | От запроса |
|---|---:|
| Первая полная модель и экспорты R5 | 27 мин20 с |
| Чистовой финальный вид R7 | 36 мин34 с |

Между R5 и чистым PNG около9 мин14 с. Это wall-clock всего процесса с чтением растра, root/agent согласованием, CAD-командами, восстановлением после ошибок и подготовкой вида. Внутреннее вычислительное время CAD kernel отдельно не замерялось; не использовать этот интервал как скорость одной CAD-операции.

## Находки для повторения готового workflow

1. В этом native сеансе нормаль YZ потребовала reverse=True для вырезания в сторону+X. Первая операция не сняла материал; штатная проверка изменения объёма остановила процесс. Ошибочный feature удалён готовым delete_feature только из собственной детали после проверки identity; чужие документы не менялись.
2. FastMCP JsonValue может вернуть api_invoke как `{result: value}`. Для чтения identity/bool/параметров применён уже имеющийся helper из upstream scripts/validate_advanced.py; первоначальные false mismatch не являются доказательством рассинхронизации API5/API7.
3. Предварительная оценка объёма пазов была approximate; клиентский порог0.1 мм³ оказался необоснованно строгим. Проверены реальные ширины/грани, допуск для этой численной оценки1 мм³ записан отдельно от геометрических размеров чертежа.
4. Эскизы и базовые плоскости могут попадать в native raster export. Для чистого вида использован существующий set_entity_state/SDK hidden=True только для своей вспомогательной геометрии, без suppression тела. Для300dpi использован штатный RasterFormatParam/SaveAsToRasterFormat вместо нового renderer.
