# Simulator: состояние и перспективы

[Индекс](../index.md) · Исходный HEAD: 7b2d852f261e372838f817ad703f7b07083329fc, 19.07.2026. До аудита 10 файлов / 2 коммита. Удалённый HEAD origin проверен 07.11 и совпал с локальным.

## Что реализовано

Один ROS 2 пакет **robohand_description** на ament_cmake, [package.xml](../../robohand_ws/src/robohand_description/package.xml). [Xacro](../../robohand_ws/src/robohand_description/urdf/robohand.urdf.xacro) описывает J1–J6, tool_link и виртуальный параллельный захват с mimic. Геометрия — примитивы, длины и инерции приблизительные. [Launch](../../robohand_ws/src/robohand_description/launch/display.launch.py) создаёт robot_state_publisher, joint_state_publisher_gui и RViz.

Пакеты robohand_gazebo и robohand_bringup из README пока не созданы. Worlds, physics plugins, controllers, ros2_control hardware interface и эксперимент grasp/release отсутствуют. Это описание кинематического скелета и подготовка визуализации, а не подтверждённый цифровой двойник физической EB300.

## Проверено 07.11.2026

В существующей WSL Ubuntu-22.04 / ROS 2 Humble выполнена новая colcon build с отдельными build/install/log в /tmp: **1 package finished, exit 0**. После source свежей установки xacro успешно создаёт URDF: **10 links, 9 joints** — 6 revolute, 2 prismatic и 1 fixed. Тегов gazebo и ros2_control нет. Создание launch description даёт 4 entities; сами узлы и GUI не запускались.

До аудита в игнорируемом log/build_2026-05-25_22-22-52 уже лежал успешный исторический configure/build/install с rc=0. Это доказательство прежней сборки, не прохождения динамического теста. Последний июльский коммит менял только scripts/install_ros2_humble.sh.

## Расхождения документации и реализации

1. [kine_eb300_approx.yaml](../../robohand_ws/src/robohand_description/config/kine_eb300_approx.yaml) не читается. Xacro объявляет config_file, но свойства base_height, L1–L6, радиусы, ход захвата и ограничения заданы числами внутри XML. Launch также не передаёт набор параметров геометрии.
2. Повторная генерация с config_file:=/tmp/nonexistent-robohand-audit.yaml прошла успешно и создала побайтно идентичный URDF. Поэтому инструкция README «правьте YAML» пока не меняет модель.
3. Путь /mnt/d/__projects__/RoboHand из старых логов/инструкций на текущем компьютере отсутствует. Старый build/install содержит привязки к прежней раскладке; после переноса нужна свежая сборка.
4. Инерции, массы и пределы в модели являются предположениями. Без измеренной геометрии/ориентации осей и параметров приводов её нельзя использовать как доказательство точности, досягаемости или переноса политики.

Скрипт установки ROS не запускался. При его развитии нужно отдельно проверить права на запись keyring/source-list для ветки без root; в текущем коде sudo используется для apt, а перенаправления файлов выполняет сам shell.

## Следующий самостоятельный результат

Подключить YAML как реальный источник параметров и подтвердить, что изменение длины/лимита меняет URDF. Зафиксировать измеренные геометрические размеры, оси, нули и систему координат инструмента. Затем проверить RViz в GUI. Gazebo и контроллеры добавлять после определения конкретного сценария проверки.

Для первой физической записи демонстраций завершённая динамическая симуляция не обязательна. Description остаётся полезен для TF, визуализации и проверки координат. Миграция ROS не является текущим аппаратным блокером: Humble уже работает; долгую новую ветку стоит планировать с учётом поддержки до мая 2027.
