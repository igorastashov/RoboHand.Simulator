## Что означает выбранный маршрут

π0.5 — предобученная VLA, из которой получаем исполнителя нашей руки через поддерживаемую адаптацию/LoRA и демонстрации. Планируем локальный inference; реальная память обучения и качество измеряются отдельно. Внешний GPU допустим при необходимости. Две3090 не являются автоматически одной48GB картой. Ни LoRA, ни наличие весов не отменяют robot/action/camera/data contract.

По [LeRobot benchmark table](https://huggingface.co/docs/lerobot/pi05) π0.5 показывает97,5% среднего LIBERO success в указанном протоколе после task-specific training. Это не результат базовой модели на EB300. В [Robbyant comparison](https://github.com/Robbyant/lingbot-vla-v2/tree/be969b8fd117fb70550c5d4bf4bc328211b5b1b6) π0.5 уступает LingBot-VLA2.0 на их RoboTwin2.0 clean/randomized evaluation. Поэтому π0.5 — сильный поддерживаемый baseline, не объявленный универсальный SOTA на конец2026. Смена модели рассматривается по одинаковой проверке нашей задачи, а не по несопоставимым процентам разных benchmarks.

## Токенизатор: конкретный следующий вход владельца

Штатный preprocessor π0.5 использует `google/paligemma-3b-pt-224`. Anonymous HTTP requests к `tokenizer_config.json`/`tokenizer.model` получили401. Владелец подтвердил аккаунт и самостоятельно скачивает доступные ему файлы в `C:\Users\igora\Downloads`, сообщит о завершении. До этого полный text→processor→action smoke не объявляется пройденным.

Для локального tokenizer directory нужны `tokenizer.json`, `tokenizer.model`, `tokenizer_config.json`, `special_tokens_map.json`; `added_tokens.json` также сохраняем, если предоставлен. Отдельные11,7GB PaliGemma weight shards не нужны. Исходные browser downloads сохраняются; нужные файлы копируются наE после завершения и проверки, затем применяется штатный `text_tokenizer_name`/processor override. Авторизация/скачанные gated assets не публикуются в Git.

## Почему свободный карандаш пока не берётся

Read-only URDF audit подтвердил6movable joints J1–J6; все gripper visual geometries находятся на `wrist3_link`, отдельного gripper joint/actuator нет. Native snapshot имеет25saved mates, но это само по себе не готовая физическая кинематика захвата. Manufacturer README EBG-20 указывает один MG995 servo или выше.

Следующий physics deliverable — отдельные движущиеся тела/связи EBG20, обоснованные linkage/drive limits, раскрытие/закрытие и свободный карандаш с контактным удержанием. До этого нечестно проверять learned pickup: прежний fixed attachment удерживает палочку независимо от модели. Принятую `E:\RoboHand\LATEST\CAD\EB300.a3d` сохраняем.

## Isaac Sim, Newton, Isaac Lab и Omniverse в этом маршруте

| Часть | Роль |
|---|---|
| Физический симулятор | Суставы/приводы/контакты/предметы и следующий кадр после движения. Уже подготовленные MuJoCo/native assets сохраняются |
| Isaac Lab | Готовые среды, data collection и evaluation/training workflows, в том числе параллельные; конкретная policy training method задаётся отдельно |
| Newton / PhysX | Выбираемые physics backends поддерживаемого workflow; «Isaac Sim + Newton» не означает обязательное одновременное включение обоих движков |
| Isaac Sim / Omniverse | Сцена, материалы, виртуальные камеры и при необходимости RTX rendering. Omniverse не обучает зрение отдельным магическим этапом |
| π0.5 + LoRA | Учится по demonstrations через свой официальный supervised/flow-matching workflow; получает frames/state/instruction и предсказывает actions |

[Актуальная Isaac Lab installation](https://isaac-sim.github.io/IsaacLab/main/source/isaaclab/installation.html) разделяет Newton default и optional Isaac Sim. [Isaac Sim](https://docs.isaacsim.omniverse.nvidia.com/latest/index.html) использует Omniverse для simulation/rendering. Наличие тысяч виртуальных копий не заменяет demonstrations для выбранного LoRA метода. Новый массовый RL/PPO цикл в план руки не возвращается. Для первого π0.5 smoke устанавливать весь Isaac Sim stack не требуется.

## Ближайшие итерации по выходам

1. Base weights/GPU → finite action chunk, actual peak VRAM/latency и отдельный статус tokenizer/sample. Текущая итерация.
2. После browser downloads → штатные tokenizer/preprocessor и reference real-batch `select_action`. Сначала проверяем формат/исполнение, затем память поддерживаемого LoRA update; это не обучение EB300.
3. EBG20 → управляемое раскрытие и физический хват свободного инструмента. Камера остаётся одной wrist Redmi8A, полный кадр без crop/zoom/external views.
4. Готовый recorder/robot contract → пилотные demonstrations EB300, затем LoRA и held-out grasp evaluation. Если нужен новый исполняемый bridge/model adapter, предъявить конкретный gap/scope до его написания.
